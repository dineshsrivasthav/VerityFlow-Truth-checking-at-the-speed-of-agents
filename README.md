# Article Assurance Validation Service

## Overview

Article Assurance Validation Service is a lightweight trust evaluation layer for validating externally retrieved information before it is consumed by downstream agentic workflows, reasoning systems, or RAG pipelines.

The system evaluates retrieved articles across three trust dimensions:

* Publisher Reputation
* Provenance and Originality
* Cross-Source Corroboration

Each article is independently analyzed while also being evaluated relative to other retrieved articles belonging to the same event cluster. The service produces metric-level scores, aggregate trust score, and a final validation decision.

The implementation is deterministic, modular, explainable, and optimized for integration into production workflows.

# `article_assurance/api.py`

Primary Python integration interface.

Exposes the `AssuranceService` class which acts as the external programmatic entrypoint to the validation engine.

Example usage:

```python

result = service.assess(payload)
```

This layer abstracts internal orchestration and provides a clean interface for agentic workflows and external services.

# `article_assurance/core/`

Contains shared infrastructure, internal schemas, semantic inference context generation, normalization logic, and reusable utilities.

---

## `core/config.py`

Centralized configuration management.

Defines:

* model names
* scoring weights
* validation thresholds
* penalty values
* API configuration
* semantic similarity thresholds

All scoring calibration values are controlled from this file.

---

## `core/context.py`

Builds the shared semantic inference context used across the entire pipeline.

Computes:

* sentence embeddings
* cosine similarity matrix
* NLI inference matrix

The context is generated once per request and reused across provenance and corroboration scoring to avoid repeated transformer inference.

This is one of the primary performance optimization layers in the system.

---

## `core/models.py`

Contains all Pydantic data models used throughout the project.

Defines:

* input schema
* normalized article schema
* score objects
* output schema
* validation enums

Ensures strict type validation and consistent data contracts across the pipeline.

---

## `core/normalizer.py`

Transforms heterogeneous article inputs into a unified internal representation.

Normalizes differences between:

* news articles
* government releases
* trade body publications

This layer standardizes:

* publisher fields
* source types
* timestamps
* article identifiers

before downstream scoring.

---

# `article_assurance/reputation/`

Publisher reputation evaluation engine.

Evaluates structural trustworthiness of article source infrastructure independent of article content.

---

## `reputation/engine.py`

Main reputation orchestration layer.

Coordinates URL validation, heuristic scoring, optional external enrichment, and final reputation aggregation.

---

## `reputation/url_validator.py`

Performs structural URL analysis.

Checks:

* HTTPS usage
* suspicious URL patterns
* malformed domains
* lexical anomalies
* risky TLD usage

Produces deterministic URL verification scores.

---

## `reputation/scoring.py`

Computes final publisher reputation score by combining:

* URL verification
* domain verification
* source-type priors
* optional APIVoid adjustments

This file contains all weighting logic for reputation evaluation.

---

## `reputation/fallback.py`

Primary heuristic-based reputation scoring implementation.

Used as the default reputation evaluation layer and as fallback protection when external API enrichment is unavailable.

Implements:

* domain heuristics
* institutional priors
* structural domain analysis

The system remains fully functional even if all external services fail.

---

## `reputation/apivoid_client.py`

Optional APIVoid integration layer.

Used only as supplementary signal enrichment for domain trust assessment.

External API scores never directly control validation decisions and are treated only as bounded confidence adjustments.

---

# `article_assurance/provenance/`

Provenance and originality scoring engine.

Evaluates temporal coherence, reporting lineage, semantic originality, and informational completeness.

---

## `provenance/engine.py`

Main provenance orchestration layer.

Coordinates all provenance-related scoring modules and computes the aggregate provenance score.

---

## `provenance/lineage.py`

Computes reporting lineage score.

Evaluates:

* publication lag relative to cluster
* derivative attribution phrases
* likely secondary reporting behavior

Used to estimate proximity to primary reporting.

---

## `provenance/temporal.py`

Computes temporal consistency score.

Checks whether publication timing is coherent relative to:

* event timing
* cluster publication distribution

Detects anomalous timing behavior and inconsistent reporting windows.

---

## `provenance/originality.py`

Computes semantic originality score using embedding similarity.

Measures whether an article demonstrates:

* healthy corroborative alignment
* excessive duplication
* semantic drift from the event cluster

This module relies on the shared semantic context generated in `core/context.py`.

---

## `provenance/completeness.py`

Computes structural completeness score.

Evaluates whether the article contains sufficient informational content for reliable assessment.

Checks:

* title length
* summary length
* content length

---

## `provenance/scoring.py`

Aggregates all provenance metrics into the final provenance and originality score using weighted scoring logic.

---

# `article_assurance/corroboration/`

Cross-source corroboration engine.

Evaluates how strongly an article is supported by the broader evidence field.

This is the primary semantic validation layer in the system.

---

## `corroboration/engine.py`

Main corroboration orchestration layer.

Coordinates similarity scoring, NLI support evaluation, evidence graph construction, and consensus aggregation.

---

## `corroboration/diversity.py`

Computes source diversity score.

Measures independent publisher spread within the event cluster.

Used to reduce amplification bias caused by repeated syndication.

---

## `corroboration/similarity.py`

Computes inter-article semantic similarity score using cosine similarity over shared embeddings.

Measures semantic consistency between articles discussing the same event.

---

## `corroboration/nli.py`

Computes semantic entailment support using transformer-based Natural Language Inference (NLI).

Evaluates whether articles:

* support
* contradict
* remain neutral

relative to one another.

This is one of the strongest semantic reasoning signals in the system.

---

## `corroboration/graph_builder.py`

Constructs the directed evidence graph.

Nodes represent articles and weighted edges represent semantic support relationships derived from NLI inference.

Used for consensus propagation analysis.

---

## `corroboration/consensus.py`

Computes graph consensus score.

Measures aggregate incoming evidentiary support for each article using graph-based reasoning.

---

## `corroboration/scoring.py`

Aggregates all corroboration metrics into the final cross-source corroboration score.

---

# Article Schema

## News

```json
{
  "title": "string",
  "source": "string",
  "event_date": "YYYY-MM-DD",
  "date_published": "ISO datetime",
  "content": "string",
  "summary": "string",
  "url": "string"
}
```

Government articles replace `source` with `issuer`.

Trade body articles replace `source` with `organization`.

---

# Output Schema

```json
{
  "query": "string",
  "event_date": "string",
  "validated_articles": [
    {
      "article_id": "string",
      "source_type": "string",

      "publisher_reputation": {},
      "provenance_originality": {},
      "cross_source_corroboration": {},

      "final_trust_score": 0.0,

      "decision": "valid | uncertain | invalid",

      "is_valid": true
    }
  ]
}
```

# Validation Decisions

| Decision  | Description                                           |
| --------- | ----------------------------------------------------- |
| valid     | High-confidence trustworthy article                   |
| uncertain | Moderate-confidence or partially corroborated article |
| invalid   | Low-confidence or weakly supported article            |
